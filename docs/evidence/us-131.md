worker process. The fixture pauses a worker-reported staging event for 700 ms to

isolated inspection/validation handler against a real FFmpeg-generated upload.

Assertions: stage/percentage visible without manual refresh; completed metadata
and validation update; controlled worker failure shows only `Processing failed.`;
Retry creates a distinct queued successor; predecessor remains identical; the
successor executes and completes; timeout 300000 ms/max attempts 2; one Project
stream across two visible uploads and retry; zero document loads and unchanged
`performance.timeOrigin`; no horizontal overflow at mobile width; no unsafe
fixture failure text appears in the DOM. Validating, probing, decoding and
finalizing percentages/events are retained in the trace. The control fixture is
loopback-only test code and is absent from production routes/images.

[Concurrent retry](us-131-concurrent-retry.json) records two authenticated
Owner/Editor requests selecting one Failed predecessor, one durable winner,
real BullMQ reservation, unchanged predecessor, and normal Queued publication.
API tests additionally cover all six statuses, no Job yet, same-time successor
history ordering, role/non-disclosure/UUID matrix, CSRF, active/completed retry
conflicts, cancellation, and safe projection without payload/failure_reason.

missed while disconnected is not replayed. Unknown initial identity is recovered
by live discovery, reconnect, or explicit Refresh job status.
