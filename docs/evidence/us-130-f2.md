## Scope and enforcement

Only SSE forced cleanup, its watchdog, tests and contract documentation change.
Normal close remains graceful. Slow timeout and bounded state-buffer overflow use
idempotent cleanup followed by TCP `resetAndDestroy()` and `response.destroy()`.
The reset releases kernel transmit queues as well as the Node connection handle.
A plain response destroy was also investigated: it removed ESTAB but left roughly
3.54 MB in FIN_WAIT1, so the final path resets the TCP socket explicitly.

One watchdog measures 5000 ms from the last successful Node write callback or
`drain`, using a monotonic clock. Once write returns false it computes the remaining
interval, including immediate destruction if the confirmed-progress deadline has
already expired. New queued events do not extend that interval. Unit tests exercise
stale deadlines, actual write completion, no reset by queued reports, ordinary
close and idempotent timer/listener/buffer cleanup.

SSE cannot identify the exact instant a remote application stops reading. Kernel
buffers may continue accepting output before Node sees backpressure. The bounded
watchdog guarantees forced cleanup once non-draining output is observed, rather
than promising a five-second connection lifetime after a browser stops reading.
See the [contract](../contracts/job-events.md).

HTTP/TCP sockets, production JWT authentication/project authorization, PostgreSQL
and Redis pub/sub. Three clients pause reads after the authenticated SSE headers;
one healthy client keeps reading. No mock write results or altered kernel buffer
sizes are used. **16000 valid synthetic progress events** reproduce the heavy case.

Before: all three responses ended about 5000 ms after write returned false, but
server sockets remained ESTAB with approximately 3.54 MB each queued. The new
assertion failed as expected, and test-owned connections were cleaned up normally
in `finally` so the command terminated.

with **0 kernel queued bytes**, **0 Node writable bytes**, and no SSE drain/close
listeners remaining. A retained connection tuple makes the kernel check independent
of Node clearing its socket metadata after close.
